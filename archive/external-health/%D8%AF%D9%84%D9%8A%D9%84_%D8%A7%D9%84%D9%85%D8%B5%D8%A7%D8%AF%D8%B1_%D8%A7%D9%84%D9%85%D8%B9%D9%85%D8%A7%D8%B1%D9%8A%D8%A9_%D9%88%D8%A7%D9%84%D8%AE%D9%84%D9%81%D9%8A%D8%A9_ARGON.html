المعمارية الخلفية المقترحة لـ ARGON

1. نواة Modular Monolith

Java + Spring Boot + Spring Modulith. مجالات مستقلة داخل تطبيق مضبوط الحدود، مع اختبار تلقائي يمنع الاعتمادات العشوائية. لا تبدأ بميكروسيرفس لكل مجال دون حاجة مقاسة.

2. مصدر الحقيقة

PostgreSQL للبيانات المنظمة والمعاملات، مع مخطط وصلاحيات وتدقيق وإصدارات واضحة. Redis/البحث/التحليلات مشتقات قابلة لإعادة البناء، وليس مصدر حقيقة موازيًا.

3. واجهات وتكامل

OpenAPI للـ REST الداخلي، وFHIR R4/R4B على حدود التبادل حسب ملف التنفيذ، وHL7 v2 للموروثات، وDICOM/DICOMweb للصور. العقود والـ profiles والاختبارات جزء من المنتج.

4. هوية وتفويض

OIDC/OAuth2 عبر مزود هوية، وصلاحية لكل طلب في الخادم، وعزل tenant، وسياسات قاعدة البيانات كدفاع إضافي، وهوية مستقلة للخدمات، وعمليات break-glass محدودة ومدققة.

5. أحداث موثوقة

معاملات + Outbox/سجل نشر، مستهلكون idempotent، retries محدودة، DLQ وتنبيه ومخطط إصدارات للأحداث. أضف وسيط رسائل أو محرك workflow فقط عندما تتطلبه العمليات.

6. تشغيل آمن

OpenTelemetry، مؤشرات وتنبيهات، نسخ احتياطي واستعادة مجربة، إدارة أسرار، SBOM وفحص تبعيات وتوقيع إصدارات، واختبارات حمل وتهديدات وتكامل قبل الإطلاق.

رحلة البيانات الأساسية التي يجب أن يدعمها backend

Identity + Tenant←Patient / MPI / Consent←Encounter / Clinical record←Orders←Lab / Radiology / Pharmacy←Results / Review←Billing / Claims / Payment

كل خطوة تحتاج حالة دورة حياة، وهوية منشأة ومستخدم، وتوقيتًا موثوقًا، ومصدرًا للمعلومة، وسجل تعديل، وسياسة وصول، وسلوك فشل، واختبارات. البيانات السريرية لا تُختزل إلى عدد جداول؛ عمقها يأتي من سلامة المعنى والعلاقات والتاريخ والمصدر والحالات والاستثناءات.

قائمة تدقيق لاختيار أي مستودع

البندأسئلة يجب إجابتها
الصيانةهل توجد إصدارات حديثة؟ هل الـ maintainers نشطون؟ ما سياسة الدعم والثغرات؟ هل هناك إصدارات LTS أو سياسة deprecation؟
الأمانهل توجد CI وtests وCodeQL أو فحوص مشابهة؟ هل تُراجع الاعتمادية والتبعيات؟ هل توجد عملية إفصاح عن الثغرات؟
الرخصةهل الرخصة تسمح بالاستخدام والتعديل والتوزيع التجاري كما تخطط؟ هل جميع الحزم الفرعية والتبعيات لها شروط مفهومة؟
الملاءمة الطبيةهل يدعم المجال المطلوب فعلًا؟ هل توجد نماذج وسير عمل سريرية؟ ما حدود استخدامه وما الذي لا يغطيه؟
التشغيلهل توجد وثائق النسخ والاستعادة والتحديث والمراقبة؟ هل تستطيع تشغيله وتحديثه واستعادة بياناته بفريقك؟
التوافقهل توجد ملفات FHIR/DICOM/HL7 محددة واختبارات توافق؟ هل يدعم السوق أو الشريك المستهدف أم يحتاج محولًا؟
تحذير مهم: لا تجمع PostgreSQL وRedis وKafka وRabbitMQ وPub/Sub وTemporal وmicroservices جميعها لمجرد أنها أدوات معروفة. كل إضافة تزيد سطح الهجوم والتكلفة والعمليات والفشل. ابدأ بنواة متماسكة، وسجل قرارًا لكل تقنية، وأضفها عندما يظهر احتياج مثبت.

المراجع التي يجب أن تعتبرها خط أساس مستمرًا

  • HL7 FHIR R4 وملفات التنفيذ الخاصة بالسوق أو الشريك.
  • OWASP ASVS 5.0 وOWASP API Security Top 10.
  • NIST SSDF وSLSA لسلسلة التوريد.
  • PostgreSQL RLS وBackup & Restore.
  • OpenTelemetry وGoogle SRE Workbook لعمليات القياس والموثوقية.
أُعدّ هذا الدليل في 10 أكتوبر 2026. الروابط تقود إلى المصادر الأصلية حيث أمكن. حالات الإصدارات والرخص والمعايير قد تتغير؛ راجع المصدر الأصلي عند اعتماد قرار تقني أو تجاري. هذا دليل هندسي لا يمثل شهادة أمان أو اعتمادًا طبيًا أو استشارة قانونية.
